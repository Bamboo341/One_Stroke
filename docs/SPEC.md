# 一筆書きパズルソルバー 仕様書 v1.1

## 1. 概要
ユーザーがGUI上で図形（点と線）を入力すると、一筆書き（オイラー路）が
可能かを判定し、可能な場合は実経路を「各線の通過順の番号」と
「点のラベル列（例: D → A → B → C）」で提示するデスクトップアプリ。
有向グラフモードでは線に向きを持たせ、矢印の向きに沿った一筆書き
（有向オイラー路）を扱う。

## 2. 技術要件
- Python 3.10 以上 / GUIは tkinter（標準ライブラリ）
- 外部ライブラリ使用禁止（pip install 不要で動くこと）
- 対象OS: Windows を主とし、macOS/Linux でも動作すること

## 3. ファイル構成
| ファイル | 役割 |
|---|---|
| graph_logic.py | ロジック層。tkinter を import しない |
| gui_app.py | GUI層。エントリポイント（python gui_app.py で起動） |
| test_graph_logic.py | ロジック層の単体テスト（unittest） |

## 4. 用語
点=頂点 / 線=無向辺 / 次数=点に接続する線の本数 /
奇数点=次数が奇数の点 / 多重辺=同じ2点間の複数の線 /
オイラー路=全ての線をちょうど1回ずつ通る経路（閉路は始点=終点の場合）

## 5. データ構造（graph_logic.py）
### Point
id: int（一意）/ label: str / x, y: float（Canvas座標）
### Edge
id: int（一意）/ u, v: int（端点の点ID）/ other(pid) で反対側の端点を返す
### Graph
- points: dict[int, Point]
- edges: dict[int, Edge]
- adjacency: dict[int, list[int]]  … 点ID → 接続する「辺ID」のリスト
- directed: bool … False=無向（既定）/ True=有向。
  有向時は Edge の u→v を向きと解釈する。このため Edge の u, v は
  add_edge で指定された順（GUIでは1点目→2点目のクリック順）を保持すること
- 採番規則: 点・辺とも専用の単調増加カウンタで採番する。
  削除後にIDを再利用しないこと。len() による採番は禁止（削除でID衝突するため）

## 6. ロジック層の機能仕様
| メソッド | 仕様 |
|---|---|
| add_point(label, x, y) -> int | 点を追加しIDを返す |
| add_edge(u, v) -> int | 線を追加しIDを返す。u == v は ValueError（自己ループ禁止）。存在しない点IDは KeyError。多重辺は許可 |
| remove_edge(edge_id) | 線を削除（存在しなければ何もしない） |
| remove_point(point_id) | 点を削除。接続する線も連動削除 |
| get_degree(pid) -> int | 次数を返す |
| get_odd_points() -> list[int] | 奇数点のIDリスト |
| get_out_degree(pid) -> int | 出次数（pid から出る線の本数。有向解釈） |
| get_in_degree(pid) -> int | 入次数（pid へ入る線の本数。有向解釈） |
| get_unbalanced_points() -> list[tuple[int, int]] | 出次数−入次数が0でない点の (ID, 差) 一覧（有向モード用） |
| parallel_edges(u, v) -> list[int] | u-v間の辺IDをID昇順で返す（多重辺描画用） |
| is_connected() -> bool | 次数1以上の点だけを対象にBFSで連結判定。孤立点は無視。辺0本なら True |
| check_if_drawable() -> tuple | (可否: bool, 理由: str, 始点ID or None, 終点ID or None) |
| find_euler_path() -> tuple | (点IDの経路列, 辺IDの通過順) / 不可能なら (None, None) |
| get_path_as_labels() -> list[str] or None | 経路をラベル列で返す |

### check_if_drawable の判定順序と内容
1. 辺が0本 → (False, "線が1本もありません。", None, None)
2. 非連結 → (False, "図形が分離しています。…", None, None)
   ※連結判定は有向モードでも向きを無視した底グラフに対して行う
3. 奇数点0個 → (True, 閉路である旨, start, start)  ※startは次数>0の点
4. 奇数点2個 → (True, 始点終点のラベルを含む文, 奇数点1, 奇数点2)
5. それ以外 → (False, 奇数点の個数とラベル一覧を含む文, None, None)

有向モード（directed=True）では 3〜5 を以下に置き換える:

3. 不均衡点0個 → (True, 閉路である旨, start, start)  ※startは次数>0の点
4. 不均衡点が「出−入=+1」と「出−入=−1」の2個 →
   (True, 始点終点のラベルを含む文, +1の点, −1の点)
5. それ以外 → (False, 不均衡点の個数とラベル一覧を含む文, None, None)

## 7. アルゴリズム要件
- 判定: オイラーの定理（連結 かつ 奇数点が0個または2個）
- 有向モードの判定: 底グラフが連結 かつ「全点で出次数=入次数」または
  「出−入=+1 の点と −1 の点がちょうど1個ずつで残りは均衡」。
  （弱連結と次数均衡が揃えば強連結性は自動的に従うため、
  連結判定は無向の is_connected を共用してよい）
- 探索: Hierholzer法。スタックによる反復実装とする（再帰禁止。
  Pythonの再帰上限を回避するため）。計算量 O(V+E)。
  各点の隣接リスト走査位置ポインタを保持して枝刈りすること。
  有向モードでは探索開始時に「出辺のみの隣接リスト」を構築し、
  それだけを走査する（逆向きには進まない）
- 使用済み判定は必ず「辺ID」単位で行う（点ペア単位は多重辺で破綻するため不可）
- 戻り値の整合: len(点列) == len(辺列) + 1、辺列は全辺をちょうど1回ずつ含む

## 8. GUI仕様（gui_app.py）
### 8.1 レイアウト
左: Canvas（白背景、初期680x500、ウィンドウリサイズ追従）
右: 操作パネル（モード選択ラジオ3種 / 「有向グラフ」チェックボックス /
［解答を探索］/ ［全て消去］/ 使い方の説明文）
下: 解答表示行 ＋ 判定ステータス行

### 8.2 モードと操作
- 点を追加: 空白クリックで点を追加。ラベルは A,B,…,Z,AA,AB,… の自動採番。
  既存の点をクリックするとリネームダイアログを表示
- 線を追加: 点を2つ順にクリックで線を追加。1点目選択中はオレンジで強調。
  同じ点を2回クリックしたら自己ループとして拒否し、選択解除して警告表示。
  空白クリックで選択解除
- 削除: 点をクリック→点と接続線を削除 / 線をクリック→その線のみ削除。
  点と線が重なる位置では点を優先
- 当たり判定: 点は中心から約19px以内、線は曲線から6px以内
- 有向グラフ切替: チェックボックスで無向/有向を切り替える。
  切替時も図形は保持し、解答のクリアと再判定のみ行う。
  線の向きは追加時のクリック順（1点目→2点目）。
  向きの反転操作は提供しない（削除して逆順で引き直す運用とする）

### 8.3 リアルタイム判定（本アプリの体験の核）
- 図形が編集されるたびに check_if_drawable を実行し、
  奇数点を赤い縁取りで強調（通常は青）、ステータス行に判定理由を常時表示。
  有向モードでは奇数点の代わりに不均衡点（出次数≠入次数）を赤で強調する
- 図形を編集した瞬間、表示中の解答（番号・始終マーカー・解答テキスト）は即時クリア

### 8.4 解答表示
- ［解答を探索］押下時、不可能ならダイアログで理由を表示
- 可能なら以下をすべて表示:
  1. 各線に通過順の番号バッジ（青丸＋白数字、1始まり）
  2. 始点の上に「始」（緑）、終点の上に「終」（赤）。閉路なら「始/終」を1つ
  3. 下部に「解答: A → B → …」のラベル列
- 番号バッジの配置: 基本は各線の曲線中点。他のバッジ・点・矢じりと
  重なる場合は、その線自身の曲線上（媒介変数 t∈[0.25, 0.75] の範囲）を
  中央に近い順にスライドして空き位置を探す（通過順の貪欲法）。
  全候補が衝突する場合は最も重なりの小さい位置を採用する。
  バッジは必ず自分の線の上に乗せること（帰属の曖昧さ防止）
- ［全て消去］は確認ダイアログを挟む

### 8.5 多重辺の描画
- 同じ2点間の複数の線は、2次ベジェ曲線で法線方向に等間隔（約26px）に
  ずらして描画し、重なりを防ぐ
- 描画に使う曲線のサンプル点列と、クリック判定に使う点列は同一にすること
  （見た目と判定のズレ防止）
- 曲線の形は端点IDの大小で向きを正規化し、どちら側から線を引いても
  同じ形状・同じオフセットになること

### 8.6 配色の目安
点の塗り #e8f0fe / 通常の縁 #1a56b0 / 奇数点・不均衡点の縁 #d93025 /
選択中の点 #f9ab00 / 線 #5f6368 / 番号バッジ #1a56b0 /
「始」#188038 / 「終」#d93025 / 矢じり: 線と同色

### 8.7 有向辺の描画
- 有向モードでは各線の上に、進行方向（u→v）を向いた矢じり
  （三角形、長さ約12px・幅約9px、線と同色）を描く
- 位置は曲線上の進行方向 t≈0.8（終点寄り）。接線方向に向きを合わせる
- A→B と B→A のような相互の辺は、既存の多重辺オフセット（8.5）で
  離して描画し、それぞれの矢じりで向きを区別する
- 無向モードでは矢じりを描かない（これが無向辺と有向辺の見分け方）

## 9. テスト仕様（test_graph_logic.py）
unittest でGUI非依存の以下の観点を必ず含める:
1. 四角形 → 可能（閉路: 始点=終点）
2. 家の形 → 可能（奇数点2つが始点・終点になる）
3. 十字（中心から4本、奇数点4個）→ 不可能
4. 離れた三角形2つ → 不可能（連結性）
5. 空グラフ → 不可能
6. 孤立点があっても判定結果に影響しない
7. ケーニヒスベルクの橋（点4・多重辺含む線7本）→ 不可能
8. 自己ループ追加 → ValueError
9. 点削除で接続線が連動削除される
10. 削除後に点IDが再利用されない
11. 経路の妥当性: 全辺をちょうど1回使用 / 経路上の隣接2点はその辺の両端と一致 /
    点列長 = 辺列長 + 1
12. 2点間に多重辺2本のみのグラフで経路が求まる
13. 不可能な図形で find_euler_path が (None, None) を返す
14. 有向の三角形閉路（A→B→C→A）→ 可能（始点=終点）
15. 有向パス（A→B→C）→ 可能。始点が+1の点、終点が−1の点になる
16. 合流する2辺（A→B, C→B）→ 不均衡で不可能、(None, None)
17. 相互の2辺（A→B と B→A）→ 可能（閉路）
18. 同一図形でも無向では可能・有向では不可能となるケース
    （例: U→V の多重辺2本）
19. 有向経路の妥当性: 各辺を u→v の向きどおりに通過する
20. 有向モードでも連結判定は向きを無視する（底グラフで判定）

## 10. 受け入れ基準
- python -m unittest test_graph_logic -v が全件パスする
- python gui_app.py でGUIが起動し、8章の操作がすべて動作する
- 家の形（点5・線6）を入力→探索で、番号1〜6・始/終マーカー・ラベル列が表示される
- 封筒の形（四角形＋対角線2本＋屋根）を探索しても番号バッジ同士が重ならない
- 有向モードで三角形（A→B→C→A）を入力すると矢じりが3つ表示され、
  探索で番号1〜3と閉路の解答が表示される
- graph_logic.py に "import tkinter" が含まれない
